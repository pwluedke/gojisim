# GojiSim

GojiSim: web-based Godzilla Card Game simulator. TypeScript engine, React/Vite web app, Node/Socket.io server.

## Setup

Requires [nvm](https://github.com/nvm-sh/nvm) (or any Node version manager that reads `.nvmrc`).

```sh
nvm use          # Node 22 LTS, from .nvmrc
corepack enable  # provides the pnpm version pinned in package.json
pnpm install
pnpm test        # Vitest across all packages
pnpm e2e         # Playwright (first run: pnpm --filter @gojisim/web exec playwright install chromium)
```

Other root scripts: `pnpm lint`, `pnpm typecheck`, `pnpm build`, `pnpm scrape` (refresh card data, see `tools/scraper`), `pnpm survey` (regenerate the ability survey in `docs/abilities/`), `pnpm abilities:coverage` (every card's ability status: implemented, partial or manual; `--set`, `--status`, `--json`). `pnpm bench` (engine speed: clone, applyAction, getLegalActions, random games per second; `--check` is the CI speed guard, which fails if `applyAction` or `getLegalActions` is more than 50 % over `bench/baseline.json` (fixed EBP01/EBP02 games, median of 9 rounds, in units of a fixed JavaScript workload), and `--update-baseline` rewrites the baseline in a PR that accepts a slowdown on purpose; the baseline is measured on the CI runner, so copy the `measured` numbers from that PR's Speed guard log into `bench/baseline.json`), `pnpm bots --a greedy --b random --games 400 --seed s --decks official` (bot tournament between `random`, `weighted`, `greedy`, `ismcts` and the difficulty presets `easy`, `medium`, `hard`; `--a-settings difficulty=70` or `samples=4` passes bot settings; `--workers 16` plays games in parallel; `--decks mixed` plays the two starters and random EBP01–EBP04 test decks, each pairing twice with the seats swapped; `hard-m12`, `medium-m12` and `easy-m12` are the search bot before M13a, to compare against (they also know their opponent's decklist, as every bot did before hidden decklists); `hard-open` is the current Hard with its opponent's decklist, and a `knowsDecklists=true` setting does the same for any bot (tools only: in the game a bot knows only its own decklist and works out the opponent's from what is played, `packages/bot/src/deckGuess.ts`); a `w.<feature>` setting such as `w.position=0.8` overrides one evaluation weight; `rollout=tactical` plays out with the tactical policy (take a winning invasion, block an open zone 8) instead of the weighted one; `priorVisits=20` starts each new search node with 20 virtual visits at its static evaluation (M13c, off by default); report in `bot-reports/`, with the median, p95 and maximum milliseconds per decision; each finished game is journaled in `bot-reports/runs/`, so a run stopped part way, by a crash or a restart, plays only its missing games when the same command runs again). `pnpm search-rate --a-settings priorVisits=20 --games 10 --shard 0/5 --out file.json` measures each bot's searches per move at the browser's 1 s budget, bot a against bot b over timed games (run 5 shards side by side, alone on the machine); fixed-search trials then give each bot `iterations=<its mean>` with `--deterministic`, so trials can share the machine. `pnpm bot-explain <record> --at <index>` prints a bot decision from a game record: every legal action with its search visits and mean value from the bot's own view, the one it picks and the actions pruned as dead (`--list` lists the record's bot decisions; `--difficulty`, `--seed`, `--max-ms`, `--set key=value`). `pnpm bot-positions` runs each position in `tools/bots/positions/` (a game record cut at a bot decision, with action keys to avoid or prefer) over 20 seeds at Hard and 100 and prints how many pass (`--dir` for another folder, `--settings`, `--max-ms`); `--from <record> --at <index>` writes a position from a game record instead, avoiding the action played there. `pnpm feedback` downloads the uploaded game records from the server and writes one Markdown summary of the new Report bug, Good Bot! and Bad Bot! reports, with the human's win rate by bot level (docs/deploy.md); `pnpm bot-feedback <records folder>` lists every Bad Bot!, Good Bot! and Report bug entry once each (a game's uploads count as one game), with the bot's move in plain words and its stored label under it (`--kind bad`, `good`, `bot` or `bug` for one kind).

## Debug viewer

`pnpm --filter @gojisim/web dev`, then open `http://localhost:5173/`: a menu with Play vs bot and Debug. `/play` is the game board, human vs bot (or two bots; hotseat was removed in M5h until online play), (M5, in progress), laid out like the official playmat: click a hand card to light its destinations and click one, or drag the card there (cards that can be played to a zone are lit; any card can still be selected to invade or gain rage); hover any card for the preview panel; Esc cancels. The left column's prompt shows the step, the turn flags, Pass [Space] (every Pass asks "End Main and move to the Counter Phase?"; a second Space confirms, Esc cancels) and Concede; every choice opens a modal (number keys 1 to 9, hold the eye button to see the board; target cards show where they are, and hovering one rings that place on the mat; a single legal target is still asked, so you see what your effect hits; the same goes for a single next monster or a single zone), and zone choices light the zones, with the zone buttons ("Your zone 1", "Bot's zone 3") in the Prompt panel, so the battle log stays clear. Start opens the board with both mats and the decks in place, and the First / Second pick shows as a modal over it (two face-down cards; the human picks; two bots skip it). The new-game checkbox "Skip First / Second pick (random first player)" (off by default, saved, in Casual and Tournament) skips the pick: the seed's random draw picks the first player, as with two bots. In a Casual game, holding Cmd (Ctrl on Windows and Linux) shows both cards face up while held, and the game record notes the peek (such games stay out of statistics); in a Tournament game the key does nothing. Your hand sits on the window's bottom edge, showing the top 40 % of each card (rank, name and the top of the art), overlapping like a held hand; hovering a card, focusing it or selecting it raises it whole at 1.5 times the board card size (a selected card stays up until the action or Esc). The bot's hand is a row of overlapping half-size card backs left of its mat, top-aligned with it, each next card showing a sixth; when the row would reach the mat, it shows one card back. Either way the rightmost card carries the bot's hand size as a count badge, like the deck's (an empty hand shows an empty slot with 0), and it changes once a card's flight lands. Card backs have a white border with a thin outline, so overlapping backs are easy to count. "Show opponent's hand" (the Test Site panel's Test settings, at any point of a game, after a warning) shows the bot's hand face up, and hovering the row fans the cards out (hover a card for the preview); the record flags the game from then on, so it never counts toward statistics or achievements. Under Settings, the Test Site panel (while the server's `GOJISIM_TEST_SITE` is on) holds **Report bug** (write what went wrong; Send uploads the game with your note, and a failed send or sharing off downloads the file instead) on its own row, then **Good Bot!** (tell us what the bot's last move got right, so later changes keep it) and **Bad Bot!** (what it got wrong) side by side, which upload the game with your note at once; its folding Test settings hold "Share finished games to improve GojiSim" (on by default: finished games upload to the server) and a "Which button?" help. Zone labels sit under the cards, so an empty area shows its name; hovering a phase tracker step shows its name and rule number. When the game ends, a modal shows the result and a line for how it ended (from `apps/web/src/play/gameOverLines.json`, one list per outcome, never the same line twice in a row); Space closes it and the board stays viewable. The history view's "Back to live" is a full-width bar at the bottom. A deck search's card pick names what is searched for, with no number badges (the number keys still pick) and no repeated location labels. Battle log lines have a left border in the acting player's color and a small colored tag for their kind (destroy, rage, draw / search / reveal / mill, play, invade / counter, combo); turn markers are bold dividers. With Show rule numbers on, each rule number shows the rule's text on hover and opens a rules panel at that rule, built from `docs/rules/comprehensive-rules-v1.2.txt`. Clicking a discard pile, a monster or a zone stack opens a read-only viewer of its cards (decks stay hidden); hovering one says so ("Discard pile: click to view", "Monster stack: click to view", "Zone 3 stack: click to view"), and the discard pile's top card still previews. The top of the log column is a fight card: your deck's name, a big "VS", then the opponent's (bundled Anton and Bungee fonts; long names shrink, then are cut with the full name on hover; a record without names reads "Mystery Deck"); it collapses with the log. Selection modals show a field card's board numbers (counter power with its modifier, change chips, a monster's threat). A win by invasion ends with the winning monster lifting onto the opponent's mat and slamming into their zone 8, with cracks and a mat shake, before the game-over modal (cracks without motion with Animation Off). Casual undos are kept in the game record (who, when, what) with a count per player; Settings → Show undone actions lists them dimmed in the log. Every yes/no ability prompt says what Yes does in plain words, then the card's text (and the step, for [invading] abilities). Dragging a card over your discard pile to invade draws a yellow arrow along your monster's path, one hop per zone (Settings → Invade arrow). Every card move animates, tokens and cards placed under others included. Long deck names are cut to fit the new-game screen, with the full name under the picker. The new-game screen fits on one screen at 1280×800 (compact 36 px controls, the seats side by side, My decks collapsed, the game options in one block at the bottom). Each seat's Randomize picks a deck from its list (what the development-deck filter shows; legal decks only in a Tournament game), with a fresh random source, not the game seed; switching between Casual and Tournament resets P1 to ESD01 and P2 to ESD02. A printed X in counter power or threat (Monster X) shows as X, and its current value as X = 12000. A game record with two human seats loads in `/debug` only. Casual games have Undo [U], back to the last draw, search, reveal, shuffle, random result or opponent action; Tournament games have none. A monster that can invade with the top card of its deck (EBP03-004) adds an "Invade with your deck's top card" button next to Pass; a battle card that can be played on top of another (EBP03-051) offers both plays when dropped on that zone. A player with a third strategy zone (EBP03-013) gets a Strategy 3 slot in the mat's corner past zone 8; a Base card's strategy mark reads "Base". Tournament games take legal decks only: on the new-game screen an illegal deck is greyed out as "(illegal)", the seat lists why (deck size, copies, Token cards, colors, the restriction list), and Start waits for a legal pick. Casual games play an illegal deck with an "Illegal deck" badge on that player's mat for the whole game (hover for the reasons). The game record stores each deck's legality at game start. Every deck search you make ends in a search modal showing what was searched for and what was found (or "0 found"). Strategy cards are turned 90° in the hand and on the discard pile so the whole card shows. Strategy zones are landscape slots, so a strategy card there shows whole, and every zone keeps clear of the mat's edge. Hand cards fill the hand row's height. The battle log column collapses to a thin strip (its button or L; remembered), and the board takes the width. When a combo from `docs/combos/combos.md` succeeds (for either player), a combo modal opens once the cards land (with a brief shake): its name, who made it, its cards (hover for the preview), steps and result, as in combos.md; Close or Space closes it, and the bot waits meanwhile. The log gets a line, e.g. `Combo: Ginza Inferno (You)`; Settings → Combo callouts turns the modal off, never the line. Settings → Theme switches Showa Poster (the default: paper, ink, poster red and marigold, Dela Gothic One and Zen Kaku Gothic New, ink borders with offset shadows, halftone dots, a red header bar with GOJISIM! ゴジシム！) / Dark / Grey / Light for every page, `/debug` included; all colors, fonts, panel borders and shadows, textures and zone outlines are `theme.css` variables, one set per theme on `:root[data-theme=…]`, applied before the first paint. Card frames and card images are never themed. Each rage zone has a counter power bar: it fills by counter power against the opponent's threat and passes the threat line once it counters (7.4.3). The combos are data in `packages/cards/data/combos/` (one file per deck, checked against combos.md by a test), detected by `@gojisim/engine`'s combo module, and counted per bot in `pnpm bots` reports. Every card move animates (drags settle into the slot, bot moves, draws, discards, searches, monster changes, evolution); a destroyed card breaks into angular shards like glass (the same way on every replay) that hang for a moment, then reassemble as they fly to where the card goes, and several destroys play together. Input and the bot wait for the animation. Settings → Announce bot plays (off by default) shows each bot action as one plain-English line in a banner over the top of the board instead of the move toast ("Bot plays Destoroyah Flying Form to zone 3", "Bot searches its deck and takes 1 card"; hidden cards are never named); its Pace slider sets how long a line stays (1.5, 2.5, 3.5, 5 or 7 s, plus 60 ms per character past 40) or Confirm (OK or Space), and the bot and its modals wait for the line. The announced kinds are data (`apps/web/src/game/announcedKinds.json`). Settings adds Animation speed (Off / Normal / Fast), Turn glow (the turn player's mat border glows in their invading monster's colors, and both monster cards glow in their own colors all the time) and Mat image (upload a PNG, JPG or WebP up to 8 MB, with scale and position and Reset; stored in the browser). The battle log in the right column groups plain-language lines by turn (card names open the preview, which covers the log while open; clicking a line shows that moment read-only until "Back to live"), the left column's phase tracker lights the step in progress, and its Settings panel holds the bot delay, rule numbers and the expanded hand. Every change in force on a card (Burst, counter power, rank and threat modifiers, cannot engage, played via Evolution or an effect) is a chip on the card; hover the chips for the full list. Shortcuts: Space Pass, 1 to 9 choices, Enter confirm selected cards, B view the board behind a modal, H expanded hand, Esc cancel / close, L log, M mute the sound, U undo (Casual), ? the list. Settings → Sound (on by default) and Volume (50%) play sound effects for both players' moves: card plays, monsters, Evolution, strategy cards, destroys, invasion stomps, the invasion-win slam and roar, counters, rage, draws, shuffles, a chime when a choice opens for you, a tick for each bot announcement, and a win or loss stinger. They follow the card animations (with Animation speed Off they play at the step), stay silent in the history view, for undos and for a loaded record's moves, and start only after your first click (browsers block audio before that). The files are CC0, listed in `apps/web/public/sounds/LICENSES.md`; `apps/web/src/game/sounds.json` maps each event to its file, volume and cooldown. A pick of 2 or more cards (discarding down, "up to N", "exactly N" with more to choose from) selects cards first, numbered in pick order, then sends them with Confirm; one undo takes the whole pick back. Every choice, search and pick modal has View board [B], Undo [U] when a Casual undo is allowed, and the large preview for a hovered card; a search can show the whole searched deck, sorted, with the cards that don't match dimmed. With the official images made (`pnpm official-images`, docs/deploy.md step 3b), every card back is the official back and the First / Second pick shows the official fronts (one of two of each, fixed by the game's seed); without them the drawn ones stay. Bring your own deck with Import deck on the new-game screen (see [Importing decks](#importing-decks)). "Load a game record" on the new-game screen continues an exported game (the M5c choice fixtures in `apps/web/e2e/fixtures` are such records; `pnpm --filter @gojisim/web e2e:fixtures` regenerates them). `/debug` (`http://localhost:5173/debug`) is the debug viewer. Pick a seed and a test deck for each player (`buildTestDeck`, ESD01 or ESD02), then play both sides. All hidden information is shown. Step back and forward through the actions, and export the game record as JSON to attach to a bug report (import loads it again). Card images appear once `pnpm images` has run. Either seat can be a bot (Seat: Bot, difficulty 0 to 100 with Easy / Medium / Hard presets). The bot thinks in a Web Worker and sees only its own view. Against a human it plays at once and hides its hidden cards (toggle); two bots wait for Play, with Pause, Step, a delay slider and a spectator view.

## Deck lists

Decks use GojiSim's plain-text deck list format (the godzilla-sim export format):

```text
# comment
[deck] Folder/Deck Name
[monster deck]
1 ESD01-001
[main deck]
4 ESD01-005
```

`/debug` imports and exports these files in the browser; importing a file again replaces decks with the same name, and Clear imported decks empties the list. Keep personal deck files in `local-decks/` (gitignored); never commit them. The dev server reads every `local-decks/*.txt` at startup and again when a file changes, and lists the decks in the `/play` and `/debug` pickers' development groups, by file and `[deck]` folder (the part of the name before the last `/`), with a filter box; `/debug` lists each file's parse errors with their lines. A browser-stored deck with a file deck's name is hidden behind the file deck. Without the folder there are no development decks, and production builds never include them (`GOJISIM_LOCAL_DECKS` names another folder; the tests use `apps/web/e2e/fixtures/local-decks`). The official starters are in `packages/cards/data/decks/`. Illegal decks are allowed everywhere, with a warning listing every failed rule (Paul's ruling, Oct 21, 2026).

## Importing decks

On the `/play` new-game screen, **Import deck** takes a pasted deck list in any of these forms (the format is detected):

| Source                           | How to copy it                                                                                                                                                   |
| -------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| godzillatcgdb.com deck page      | Open the deck (`/d/<id>`), press Cmd+A (Ctrl+A), then Cmd+C (Ctrl+C), and paste. The counts come from the card badges.                                           |
| godzillatcgdb.com printable list | On the deck page click Print deck list, select all, copy and paste.                                                                                              |
| godzilla-sim                     | In the Deck Builder, Export to Clipboard (one deck) or Export All Decks. Both are GojiSim deck list text; a single-deck export has no name line, so you name it. |
| GojiSim                          | Copy on a saved deck, or a deck list file (the format above).                                                                                                    |

**Decklog** (decklog-en.bushiroad.com): paste the deck's URL (`https://decklog-en.bushiroad.com/view/1STAP`) or its code (`1STAP`) into the Decklog box of Import deck and click Fetch (or Enter). GojiSim fetches it through its own route, `GET /api/decklog/<code>`, because Decklog sends no CORS header: the Vite dev server serves the route now, and `apps/server` serves the same route (`apps/server/src/decklog.ts`) at M9. The deck becomes GojiSim deck list text in the box (named after its Decklog title), so the same preview, errors and warnings apply. Parallel (`+`) and PR reprint (`++`) numbers name the same prints as the card data; a `+` print the data lacks reads as its base card. Errors: deck not found, Decklog unreachable, and card numbers GojiSim doesn't know yet (a card data refresh, `pnpm scrape`, picks up new cards). A page served without GojiSim's server (a static build) says the import needs it.

Unknown card numbers and unreadable lines block saving; legality problems (deck size, copies, the restriction list) are warnings, and the deck still plays in Casual games (Tournament games take legal decks only). A deck saves under its `[deck]` name without the folder ("Community/Red Rage" becomes "Red Rage"; editable before saving). A pasted list with several decks offers **Import all** next to the deck picker: it saves every deck that parses, reports how many were saved and which weren't, and gives a name already in My decks " (2)", " (3)" and so on. Saved decks are **My decks**, kept in this browser's IndexedDB (only for the current visit when storage is blocked), collapsed by default as "My decks (N)" and scrolling inside a box 4 rows tall when open; each deck's "⋯" menu has Rename, Copy (plain text) and Delete, and Export all / Import backup save and restore all of them as one JSON file. Saving or restoring a deck opens the list. The gitignored `local-decks` import in `/debug` stays for development.

Not supported:

- **Deck links (URLs):** the browser can't fetch a godzillatcgdb deck page (no CORS header), so import is paste only. Link import moves to M9: `apps/server` will fetch `/d/<id>` and parse its HTML.

## Card images

Card images are not committed. Run this once after cloning:

```sh
pnpm images
```

It downloads every card's original PNG from godzillatcgdb.com (1 request per second, so the first run takes about 16 minutes) into `tools/scraper/.cache/images/`, then converts each one to `apps/web/public/cards/<id>-full.webp` (original size) and `<id>-thumb.webp` (300 px wide). Reruns skip files that already exist; `pnpm images --force` re-converts. The byte sizes are recorded in `packages/cards/data/images.json`.

## Deploy for testers

The testers' build runs on Railway at `https://gojisim.somanygames.app`, behind one shared password. It deploys only by hand: Railway watches the `release` branch, which Paul moves with this command:

```
git checkout main && git pull && git push origin main:release
```

Deploy only when you want testers to get what's on main; merging a PR doesn't deploy.

See [docs/deploy.md](docs/deploy.md) for the setup steps, deploying and rolling back, the card image volume and how the gate works. `pnpm build`, then `node apps/server/dist/index.js` (with `GOJISIM_PASSWORD` and `SESSION_SECRET` set to try the gate) serves the built app locally; `pnpm --filter @gojisim/web e2e:prod` tests it with the gate on. In `/play`, **Report bug** (the Test Site panel, left column) uploads the current game record with the tester's note (it downloads the file when the send fails or sharing is off); "Load a game record" or `/debug` opens it. Finished games, Bad Bot! reports and Report bug notes upload to `/data/records` (`RECORDS_DIR`, capped at 1 GB: past it, uploads answer 507 and the server logs it once); locally the dev server writes them to the gitignored `records/`.

## Slack watcher

`pnpm slack-watch` (`tools/slack-watch`) polls #gojisim-dev every 30 s and prints one line for each Monarch message (text starting with "[Monarch]") that has no :white_check_mark: reaction yet, once per run: `[slack] Monarch <time> <first 80 characters> ts=<ts>`. Thread replies count too. Mecha starts it as a monitored background command at the start of each session, so a printed line wakes the session to check Slack. An API error prints one line and polling goes on; a rate limit (429) waits the `Retry-After` time.

Token setup (once, by Paul):

1. At <https://api.slack.com/apps>, Create New App → From scratch, in the GojiSim workspace.
2. OAuth & Permissions → User Token Scopes: add `channels:history` and `groups:history`.
3. Install to Workspace, and allow.
4. Copy the User OAuth Token (it starts with `xoxp-`). Reinstalling the app issues a new token and revokes the old one.
5. Add `export SLACK_WATCH_TOKEN=xoxp-...` to the repo's `.envrc` (gitignored) and run `direnv allow`.

The watcher reads `SLACK_WATCH_TOKEN` from the environment, or from `.envrc` directly when direnv hasn't loaded it (a background shell). It never prints the token; it sends it only in the request's `Authorization` header.
