# Bot switches

Generated by `pnpm switches` from `src/switches/` (#402): don't edit this file; edit the switch's own file.

Every bot rule or plan change goes in behind a switch that defaults to on (Paul, Nov 14, 2026), so its A/B check runs both arms on one commit: the control sets the switch off (`aSettings: "<switch>=0"` in a plan), the other arm keeps the default. A switch is a field of `IsmctsSettings` (`src/ismcts.ts`), read from a bot's settings by `ismctsSettings`. Each check on `/results` (#340) names its switch.

This list holds code facts only: no decks, lists or results. Each switch shows its default, status and where it came from. Status: **built** (in the code), **measured** (a paired check ran), **kept** (on by default after its check).

## Adding a switch

1. Add its file in `src/switches/` (`defineSwitch`: name, default (on), group, what it turns on, where it came from, status **built**), then run `pnpm switches` to update the index and this list. Its group's code reads it: a card rule from `CardRuleOptions`, a plan from its options object, the search from `IsmctsSettings`.
2. Add a test that the switch's off position is the old behavior.
3. Measure with the switch off as the control, then set the status from the result.
4. Bump `BOT_VERSION` (`src/index.ts`) in the PR that changes how the bot plays, so Kaiju Classroom's agreement on `/results` (#365) shows the change.
